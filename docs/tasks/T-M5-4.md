# T-M5-4: `/new` 経由スレッドの二重起動防止ガード

| 項目 | 内容 |
|------|------|
| マイルストーン | M5 |
| 依存 | T-M5-2, T-M5-3 |
| 要件ID | FR-006, FR-019 |

## 説明
`/new` コマンド経由でスレッドを作成した場合、`handleThreadCreate` イベントが発火しても二重にセッションが起動しないようガードする。

## 作業内容
1. `handleThreadCreate` 冒頭の `getSessionByThreadId` チェックが二重起動防止として機能することを確認
   - `/new` 側で `registerSession` した後に `threadCreate` イベントが発火
   - `handleThreadCreate` で `getSessionByThreadId(threadId)` が非 null を返す
   - 既存の `if (sessionManager.getSessionByThreadId(threadId))` で早期 return される
2. `/new` コマンド側の `registerSession` が `threads.create()` の直後に確実に実行されるよう、処理順序を検証
3. タイミング問題の検討: Discord API の `threads.create()` と `threadCreate` イベントの発火順序を考慮

## タスクのチェックリスト
- [ ] `/new` 経由で作成したスレッドが handleThreadCreate で二重起動しない
- [ ] 手動スレッド作成は従来通り handleThreadCreate でセッションが起動する
- [ ] `/new` の registerSession と threadCreate イベントの実行順序が安全に処理される
